# 릴스 해부 기준

릴스마다 아래 4개 레이어를 채운다. 결과는 `해부_결과.json` 형식(맨 아래)으로 저장한다.

## 레이어 1 · 진입각 (0~3초)
- **텍스트 채널**: 정보공백 / 이득예고 / 손실경고 / 숫자고정 / 자격증명
  - 해당하는 것 전부 적고, 겹친 개수를 센다.
  - 3초에 던진 것을 본문에서 풀지 않으면 `미끼`로 따로 표시한다.
- **화면 채널**: 결과선공개 / 통념반박 / 예상이탈 / 전후대비 / 상황공감 / 없음
- **소리 채널**: 첫 발화가 3초 안에 나왔는지
  - 위스퍼 받아쓰기가 있으면 `해부_입력.md` 의 **첫 발화** 초를 그대로 쓴다. 근거에 초와 첫 문장을 적는다.
- **일한 채널 수**: 실제로 일한 채널 수 (0~3)

## 레이어 2 · 체류 설계
- **전개형**: 문제→처방 / 의외→따라하기 / 경험→권유 / 나열
- **정보 항목 수**, **항목당 몇 초**인지
- **보류 장치**: 유형 / 몇 초에 걸었는지 / 전체의 몇 % 지점인지
  - 위스퍼 받아쓰기의 `[시작~끝초 | %]` 에서 장치 문장이 시작하는 줄의 초와 %를 쓴다.
  - 장치가 말이 아니라 화면에만 있으면 초·%는 null, `[눈으로 확인]`.

## 레이어 3 · 행동 설계
- **유도 행동**: 저장 / 공유 / 댓글 / 팔로우 / 없음
- 공유 유도면 **대상이 특정됐는지**
- **캡션 첫 줄**이 단독으로 후킹하는지
- 캡션이 본문 **반복**인지 **보완**인지
- **총정리·순위형** 구조인지

## 레이어 4 · 수요 폭
- **동기**: 재미 / 해소 / 획득
- **욕구군**: 자원 / 지위 / 역량 / 신체 / 정서
- **폭**: 좁음 / 보통 / 넓음
- 이 주제를 한 단계 넓히는 **경로 1개**

## 공통 규칙
- 모든 항목에 근거 원문을 인용한다. 근거가 없으면 `불명`.
- 영상을 봐야 아는 항목은 `[눈으로 확인]` 목록으로 따로 모은다.
  - 위스퍼 받아쓰기가 있으면: 화면 채널, 일한 채널 수, 화면에만 있는 장치만 해당.
  - Apify 받아쓰기만 있으면(시간 없음): 첫 발화 시점, 보류 장치 시점도 여기에 해당.
- 위스퍼와 Apify 받아쓰기가 다르면 위스퍼를 우선하되, 고유명사는 캡션 표기를 따른다
  (예: 위스퍼 "시경이 형" → 캡션 "성시경").
- 추측으로 채우지 않는다. 모르면 값은 `null`, 근거는 `불명`.
- 다 뜯은 다음 공통 패턴 3개를 쓴다.
- 상위 그룹과 하위 그룹의 수치 차이를 비교한다 (`compare_groups.py`).

## 해부_결과.json 형식 (릴스 1개 = 항목 1개, 전체는 리스트)
```json
{
  "url": "https://www.instagram.com/reel/...",
  "L1": {
    "텍스트채널": ["정보공백", "숫자고정"],
    "미끼": false,
    "화면채널": "결과선공개",
    "첫발화3초": true,
    "일한채널수": 3
  },
  "L2": {
    "전개형": "문제→처방",
    "정보항목수": 3,
    "항목당초": 4.5,
    "보류장치": {"유형": "끝에 공개", "초": 6.0, "퍼센트": 30}
  },
  "L3": {
    "유도행동": ["저장"],
    "공유대상특정": null,
    "캡션첫줄후킹": true,
    "캡션관계": "보완",
    "총정리형": false
  },
  "L4": {
    "동기": "획득",
    "욕구군": ["자원"],
    "폭": "보통",
    "확장경로": "..."
  },
  "근거": {"L1.텍스트채널": "\"원문 인용\"", "L2.전개형": "불명"},
  "눈으로확인": ["L1.화면채널", "L2.보류장치"]
}
```
