# 병원 네이버 블로그 원고 제작

한 병원(지점)에 대해 조사하고, 사람들이 실제로 반응하는 주제로, 병원이 직접 쓰는 목소리의 네이버 블로그 원고를 만든다. 의료법 테두리 안에서 독자의 문제를 해결하는 글이 목표다.

결과물은 프로젝트 폴더 하나에 모은다: `blog/<병원-slug>/`

```
blog/<slug>/
  00_리서치_및_주제선정.md   업체 정보, 주제 근거, 의료법 체크리스트, 원고 목록(상태 칸 포함)
  naver/0N_<주제>_네이버.txt  네이버 붙여넣기용 원고 (파일명 순서 = 원고 번호)
  prompts.json              이미지 프롬프트 (캡션 → 프롬프트)
  config.json               미리보기 페이지 설정, 게시 완료 번호
  preview.html              빌드 결과 (Artifact로 게시)
  image_prompts.txt         빌드 결과 (프롬프트 모음 파일)
```

## 1단계. 업체 조사

- WebSearch로 `<지역> <병원명>`, `<병원명> 진료 시술`, 리뷰 사이트(모두닥, 굿닥, 강남언니 등)를 검색한다.
- 정리할 것: 정확한 상호, 주소, 전화, 진료시간(출처마다 다르면 둘 다 적고 "확인 필요"), 의료진과 전문의 여부, 리뷰 사이트의 진료 키워드, 지점 칼럼·공지 주제, 주차·교통.
- 장비 보유와 가격은 공개 자료로 확인되지 않는 경우가 많다. 확인 안 된 것은 원고에 `[확인 필요 : ...]`로 남긴다. 추측해서 쓰지 않는다.
- 공식 홈페이지가 네트워크에서 막히면 검색 결과 요약만 쓰고, 그 사실을 사용자에게 알린다.

## 2단계. 반응 좋은 주제 리서치

- 유튜브·구글·언론에서 해당 진료과의 인기 콘텐츠 유형을 찾는다. 검색 예: `<진료과> 유튜브 분석 리포트 <연도>`, `<진료과> 전문의 유튜브 조회수`, 계절 고민(`가을 환절기 피부`).
- 썸트렌드(Sometrend) MCP가 연결되어 있고 크레딧이 있으면 유튜브 조회수순 문서, 네이버 블로그 연관어로 근거를 보강한다. 크레딧 부족 메시지는 그대로 전달한다.
- 검증된 인기 유형 (피부과 기준, 다른 과도 대체로 통함):
  - **판단 기준형**: 돈·후회 불안을 덜어줌 (예: A 시술 vs B 시술, 나에게 맞는 기준)
  - **생활 밀착 검증형**: 매일 하는 습관을 전문의가 점검 (세안·샤워 습관)
  - **"이건 하지 마세요" + 집에서 할 수 있는 해결법**
  - **구별법형**: 비슷해 보이는 것 구별 (여드름 자국 3종, 사마귀 vs 티눈)
  - **계절형**: 그 달의 고민 (가을 기미, 겨울 건조)
- 지점의 실제 진료 키워드와 겹치는 주제를 우선한다. 5편 + 후속 주제 백로그를 `00_리서치_및_주제선정.md`에 근거(출처 링크)와 함께 적는다.

## 3단계. 원고 쓰기

`references/writing-style.md`의 형식과 문체를 따른다. 핵심:
- 병원이 직접 쓰는 1인칭, **합니다체**. "~요"로 끝나는 문장은 첫인사 "안녕하세요." 외에는 쓰지 않는다. 이모티콘(:) 😅)과 이모지 소제목은 쓰지 않는다.
- 진료실에서 자주 듣는 질문으로 시작 → 원리 설명 → 셀프 체크 → 집에서 할 수 있는 해결법 → 이럴 땐 진료 → 짧은 맺음 → 병원 정보 → 고지문.
- 참고한 영상·기사와 문장 구성이 겹치지 않게 새로 쓴다 (네이버 유사문서 대비).
- 원고마다 제목 후보 3개, 태그 9개 내외.

반드시 `references/medical-ad-law.md` 체크리스트를 통과시킨다.

## 4단계. 이미지 자리와 프롬프트 (글마다 8장 이상)

- 원고 텍스트 안, 해당 문단 바로 뒤에 `[이미지 삽입 위치 - <캡션>]`을 넣는다. 첫 장은 1:1 대표 썸네일(`대표 썸네일 (<주제>)`), 나머지는 16:9.
- 캡션은 프로젝트 안에서 유일해야 한다 (prompts.json의 키).
- 각 캡션에 대해 `prompts.json`의 `images`에 항목을 만든다. 형식과 스타일 규칙은 `references/image-prompts.md`.

## 5단계. 미리보기·복사 페이지

1. `config.json`을 만든다 (형식은 `references/config-example.json`).
2. 빌드:
   ```
   python3 -I .claude/skills/naver-clinic-blog/scripts/build_preview.py blog/<slug>
   ```
   `ok N`, `prompts M`이 출력되어야 한다. 캡션이 prompts.json에 없으면 그 자리는 프롬프트 없이 표시되므로 M이 기대 장수와 같은지 확인한다.
3. `blog/<slug>/preview.html`을 Artifact로 게시한다 (첫 게시에 icon "article"). 이후 같은 파일 경로로 다시 게시하면 같은 URL이 갱신된다.

페이지 기능: 원고 탭, "복사하기" 화면(제목·태그·본문 전체 복사, 사진 위치 표시 켜고 끄기, 프롬프트 전체 복사), "블로그 미리보기" 화면(완성 모습, 사진 자리마다 프롬프트), 확인 필요 메모, 게시 완료 표시.

## 6단계. 게시 완료 표시

사용자가 "N번 게시 완료"라고 하면:
- `config.json`의 `done`에 번호(1부터)를 추가하고 다시 빌드·게시한다.
- `00_리서치_및_주제선정.md` 원고 목록의 상태 칸을 "✓ 게시 완료"로 바꾼다.

## 마무리

- 레포 작업이면 변경을 커밋·푸시한다.
- 사용자에게: 페이지 링크, 원고별 요약, 남은 `[확인 필요]` 항목, 막힌 조사(접속 차단, 크레딧 부족)를 알린다.
