# 병원 네이버 블로그 원고 제작

한 병원(지점)에 대해 조사하고, 사람들이 실제로 반응하는 주제와 내용을 습득해, 병원이 직접 쓰는 목소리로 새로 쓴 네이버 블로그 원고를 만든다. **의료광고 심의 테두리 안에서 독자의 문제를 해결하는 글**이 목표다. 문장과 문장은 연결어로 자연스럽게 이어 읽히게 쓴다.

결과물은 프로젝트 폴더 하나에 모은다: `blog/<병원-slug>/`

```
blog/<slug>/
  00_리서치_및_주제선정.md   업체 정보, 주제 근거, 심의 점검표, 원고 목록(상태 칸 포함), 출처
  01_지점_작성지침.md        이 병원만의 강조점·정보 박스·이미지 규칙 (references/clinic-guide-template.md로 시작)
  naver/0N_<주제>_네이버.txt  네이버 붙여넣기용 원고 (파일명 순서 = 원고 번호)
  prompts.json              이미지 프롬프트 (캡션 → 프롬프트)
  config.json               미리보기 페이지 설정, 게시 완료 번호
  preview.html              빌드 결과 (Artifact로 게시)
  image_prompts.txt         빌드 결과 (프롬프트 모음 파일)
```

같은 프로젝트에 `01_지점_작성지침.md`가 이미 있으면 모든 단계에서 그 내용을 우선한다.

## 1단계. 업체 정보 확보

**가장 정확한 출처는 네이버 플레이스다.** 작업을 시작할 때 사용자에게 네이버 플레이스 화면 내용(홈·정보 탭, 영업시간은 "펼쳐보기"를 연 상태)을 붙여 달라고 요청한다. 받기 전에는 검색으로 채우고 `[확인 필요]`로 표시한다.

- 정리할 것: 정식 상호(의원/병원 구분), 주소, 교통(출구·거리), 전화(플레이스 표시 번호), **요일별 진료시간과 점심시간·휴무**, 전문의 과목·인원(심평원 정보), 주차, 리뷰 수, 병원 블로그·채널.
- 같은 이름의 근처 지점이 있으면(예: 양재 / 도곡양재) 섞이지 않게 리서치 문서에 "혼동 주의"로 적는다.
- WebSearch로 `<지역> <병원명>`, 리뷰 사이트(모두닥, 굿닥, 강남언니)를 검색해 **진료 키워드**(리뷰에 자주 나오는 시술·질환)를 찾는다.
- 장비 보유, 시술 시행 여부, 가격은 공개 자료로 확인되지 않으면 원고에 `[확인 필요 : ...]`로 남긴다. 추측해서 쓰지 않는다.
- 공식 홈페이지 등이 네트워크에서 막히면 검색 결과 요약만 쓰고, 그 사실을 사용자에게 알린다.
- 확인된 정보로 `01_지점_작성지침.md`를 만든다 (`references/clinic-guide-template.md` 복사 후 채움). 이 병원의 **확인된 강점**(예: 피부과 전문의 N인 진료)을 여기에 적는다.

## 2단계. 반응 좋은 주제와 내용 리서치

- 구글·유튜브·언론·커뮤니티를 **여러 갈래로** 검색한다. 예: `<진료과> 유튜브 분석 리포트 <연도>`, `<진료과> 전문의 유튜브 <주제>`, `<주제> 원인 증상 하지 말아야 할`, 계절 고민(`가을 환절기 피부`), 최근 기사.
- 주제만 고르지 말고 **반응 좋은 콘텐츠가 실제로 담은 내용**(자주 묻는 질문, 흔한 실수, 생활 팁, 구별 포인트)을 모아 원고 재료로 쓴다. 근거와 출처 링크를 `00_리서치_및_주제선정.md` 표에 남긴다.
- 썸트렌드(Sometrend) MCP가 연결되어 있으면 `usage`로 크레딧부터 확인하고, 있으면 유튜브 조회수순 문서·네이버 블로그 연관어로 보강한다. 크레딧 부족 메시지는 그대로 전달한다.
- 검증된 인기 유형:
  - **판단 기준형**: 돈·후회 불안을 덜어줌 (A vs B, 나에게 맞는 기준)
  - **생활 밀착 검증형**: 매일 하는 습관을 점검 (샤워·세안 습관)
  - **"이건 하지 마세요" + 집에서 할 수 있는 해결법**
  - **구별법형**: 비슷해 보이는 것 구별 (사마귀 vs 티눈, 여드름 깊이)
  - **계절형**: 그 달의 고민 (가을 가려움, 겨울 저온화상)
- 지점의 실제 진료 키워드와 겹치는 주제를 우선한다.
- **같은 브랜드 다른 지점이 이미 쓴 주제는 각도를 바꾼다** (네이버 유사문서 대비). 사용자 저장소의 다른 `blog/*/` 프로젝트를 확인한다.
- 편수는 사용자에게 묻거나 기본 5편. 후속 주제 백로그도 함께 적는다.

## 3단계. 원고 쓰기

`references/writing-style.md`의 형식과 문체를 따른다. 핵심:
- 병원이 직접 쓰는 1인칭, **합니다체**. "~요"로 끝나는 문장은 첫인사 "안녕하세요." 외에는 쓰지 않는다. 이모티콘·이모지 소제목은 쓰지 않는다.
- **문장마다 연결어로 앞 문장과 자연스럽게 잇는다** (그래서, 하지만, 이때, 특히, 이처럼 등). 같은 연결어를 연달아 반복하지 않고, 목록·체크리스트 항목에는 억지로 붙이지 않는다. 자세한 규칙은 writing-style.md의 "문장 연결" 절.
- 구성: 진료실에서 자주 듣는 질문으로 시작 → 원리 설명(생활 비유 하나) → 셀프 체크 또는 구별법 → 하지 마세요 → 집에서 할 수 있는 해결법 → 자주 받는 질문(Q&A) → 진료가 필요한 때 → 짧은 맺음 → 병원 정보 → 고지문.
- 참고한 영상·기사와 문장 구성이 겹치지 않게 새로 쓴다.
- `01_지점_작성지침.md`의 강점(예: 전문의)을 정해진 자리에 넣는다: 첫 인사, 진료 섹션 첫 문장, 셀프 체크·구별법 뒤 "정확한 구별은 ○○ 전문의의 진찰로 확인", 정보 박스 `의료진` 줄, 태그.
- 원고마다 제목 후보 3개(시술명보다 증상·정보 중심), 태그 10개 내외.

## 4단계. 의료광고 심의 점검

`references/medical-ad-law.md`를 원고마다 통과시키고, 마지막에 **4편 전체를 다시 읽으며** 그 파일의 "최종 점검표"를 리서치 문서에 표로 남긴다 (항목 / 결과 / 조치). 걸린 문장은 고친 뒤 표에 무엇을 바꿨는지 적는다.

필수 고정 요소 (모든 원고):
- 광고 주체 정식 명칭 (인사·맺음·정보 박스 통일)
- 시술별 부작용·개인차, 전문의 상담 고지
- "본문 이미지는 이해를 돕기 위한 연출 이미지로, 실제 환자나 의료진의 사진이 아닙니다."
- `의료광고 심의필 번호 : 심의 승인 후 기재` + `[확인 필요 : 사전심의 승인 후 번호 기재, 승인 내용과 동일하게 게시]`

## 5단계. 이미지 자리와 프롬프트 (글마다 8장 이상)

- 원고 텍스트 안, 해당 문단 바로 뒤에 `[이미지 삽입 위치 - <캡션>]`을 넣는다. 첫 장은 `대표 썸네일 (<주제>)`.
- **기본은 모든 이미지 4:5 세로 실사**(`kind: "photo"`, `ratio: "4:5"`). 사용자가 다른 비율·일러스트를 원하면 지점 작성지침에 적고 따른다.
- 원리 설명도 일러스트 대신 **생활 속 비유 사물을 실사로** 찍은 장면으로 표현한다 (예: 피부 장벽 = 시멘트가 빠진 벽돌담).
- 캡션은 프로젝트 안에서 유일해야 한다 (prompts.json의 키). 캡션에 "일러스트"를 쓰지 않는다.
- 형식과 스타일 규칙은 `references/image-prompts.md`.

## 6단계. 미리보기·복사 페이지

1. `config.json`을 만든다 (형식은 `references/config-example.json`). `byline_sub`는 "피부과 전문의 진료 · 피부 건강 정보"처럼 칼럼·기고로 보이지 않게.
2. 빌드:
   ```
   python3 -I .claude/skills/naver-clinic-blog/scripts/build_preview.py blog/<slug>
   ```
   `ok N`, `prompts M`이 출력되어야 한다. M이 원고의 `[이미지 삽입 위치` 개수 합과 같은지 확인한다.
3. `blog/<slug>/preview.html`을 Artifact로 게시한다 (첫 게시에 icon "article"). 이후 같은 파일 경로로 다시 게시하면 같은 URL이 갱신된다.

## 7단계. 게시 완료 표시

사용자가 "N번 게시 완료"라고 하면:
- `config.json`의 `done`에 번호(1부터)를 추가하고 다시 빌드·게시한다.
- `00_리서치_및_주제선정.md` 원고 목록의 상태 칸을 "✓ 게시 완료"로 바꾼다.

## 정보가 새로 들어오면

사용자가 플레이스 정보, 진료시간, 강조점을 새로 주면 **모든 원고의 정보 박스와 `01_지점_작성지침.md`, 리서치 문서를 함께** 고치고 다시 빌드·게시한다. 지침은 다음 원고에도 그대로 쓰인다.

## 마무리

- 레포 작업이면 변경을 커밋·푸시한다 (컨테이너는 사라지므로 스킬·원고는 저장소에 있어야 다음에 쓸 수 있다).
- 사용자에게: 페이지 링크, 원고별 요약, 심의 점검에서 고친 곳, 남은 `[확인 필요]`, 막힌 조사(접속 차단, 크레딧 부족), 게시 전 할 일(원장 감수 → 사전심의 → 심의필 번호 기재)을 알린다.
