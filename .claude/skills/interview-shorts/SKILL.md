# 인터뷰 쇼츠 자동 편집 (캡컷 프로젝트 생성)

사용자 PC(Windows)에서 실행한다. 사용자는 비개발자이므로 설명과 질문, 보고는 쉬운 한국어로 한다.
코드는 `pipeline/` 폴더에 있고, 설정은 `pipeline/config.json`이다. 설정 파일이 없으면 `pipeline/README.md`의 설치 안내를 따라 함께 만든다.

## 받아야 할 정보

아래 세 가지를 확인한다. 빠진 것만 물어본다.
- **업체**: 예 `한방장어`
- **편**: 예 `01편`
- **원본 영상 경로**

추가로 확인할 것:
- **FFmpeg 기본 보정(`--beauty`) 여부**: 시간이 오래 걸리고 화면 전체에 적용된다고 알려준다. 정밀 보정은 캡컷 리터치를 권한다.

## 만드는 것

캡컷 프로젝트(타임라인)가 아래처럼 생긴다. 하나가 타임라인 1개다.
- `<업체>_<편>_전체`: 반복과 군말을 잘라낸 전체 편집본
- `<업체>_<편>_릴스01`, `릴스02`, …: 내용별로 자른 **1분 미만** 릴스

## 순서

모든 명령은 `pipeline/` 폴더에서 실행한다.

1. **준비**
   ```
   python step1_prepare.py --client <업체> --episode <편> --video "<경로>" [--beauty]
   ```

2. **음성 인식**
   ```
   python step2_transcribe.py --client <업체> --episode <편>
   ```
   - 그래픽카드가 없으면 오래 걸린다. 백그라운드로 실행하고 중간 진행을 짧게 알린다.
   - 너무 느리면 `--model medium`을 제안한다.

3. **편집 계획 작성 (Claude가 판단, 스크립트가 자막 분할)**
   - `{work_root}/<업체>/<편>/transcript.txt`를 처음부터 끝까지 읽는다.
   - `frames/` 사진들을 보고 인물 얼굴의 가로 위치를 판단한다.
   - 같은 폴더에 **`outline.json`**을 작성한다. 형식은 아래 "outline.json 형식"을 따른다.
     여기에는 판단만 적는다: 질문 구간과 소제목, 주제와 강조 단어, 잘라낼 구간, 릴스, 오타.
   - 그다음 아래를 실행한다. 답변 자막 분할(한 줄 14자 안팎, 최대 2줄)과 침묵 자르기는 스크립트가 자동으로 한다.
     ```
     python step3_make_plan.py --client <업체> --episode <편>
     ```
   - `step5_timeline.py`로 표를 뽑아 자막이 어색하게 끊긴 곳이나 오타가 없는지 확인한다.
     문제가 있으면 `outline.json`을 고쳐서 다시 실행한다.
   - 작성이 끝나면 **릴스 목록**(제목, 훅, 길이)과 **잘라낸 구간 수**를 사용자에게 짧게 보여준다.

4. **캡컷 프로젝트 생성**
   - 먼저 사용자에게 **캡컷을 완전히 꺼달라고** 요청하고 확인받는다.
   - 처음 쓰는 업체라면 `--only 릴스01`로 하나만 먼저 만들어서 스타일을 확인받는다.
   - 확인받은 뒤 나머지를 만든다.
   ```
   python step4_build_capcut.py --client <업체> --episode <편> [--only 릴스01] [--replace]
   ```
   - "1분 초과" 경고가 나오면 그 릴스의 구간을 줄여서 다시 만든다.

5. **타임라인**
   ```
   python step5_timeline.py --client <업체> --episode <편>
   ```
   - 출력된 표와 요약을 채팅에 그대로 보여준다.

6. **마무리 안내**: 캡컷을 열면 위 프로젝트들이 있다고 알린다. 그리고 확인할 점을 안내한다.
   - 자막 위치와 크기
   - 리터치 보정
   - 효과음과 배경음악
   - 폰트: 트랙별로 일괄 변경할 수 있다.

## outline.json 작성 규칙

**같은 말 반복 잘라내기 (`cuts`)**
- 아래 구간은 잘라낸다. 이유는 `reason`에 짧게 적는다.
  - 같은 내용을 다시 말한 부분
  - 말을 고쳐서 다시 한 부분(NG)
  - 긴 침묵
  - "음…", "어…" 같은 군말
  - 촬영 준비나 잡담
- **같은 내용을 두 번 말했다면, 더 깔끔하게 말한 쪽을 남긴다.**
- 자를 때는 `transcript.json`의 단어별 시간을 보고, 단어 중간이 잘리지 않게 앞뒤로 0.1초쯤 여유를 둔다.
- `cuts`는 전체본과 모든 릴스에 똑같이 적용된다.

**릴스 나누기 (`reels`)**
- 질문이나 주제 하나를 **한 편의 릴스**로 만든다. 한 편만 보고도 이해되게, 질문부터 결론까지 넣는다.
- `ranges`의 시간에서 `cuts`를 뺀 길이는 **59초 이하**여야 한다. 넘으면 덜 중요한 문장을 `ranges`에서 빼서 구간을 여러 개로 나눈다.
- 너무 짧으면(15초 미만) 다른 주제와 합치거나 뺀다.
- `title`: 릴스 소제목이다. 질문을 `Q. ` + 15자 안팎으로 요약한다.
- `hook`: 첫 2.5초에 크게 나오는 문구다. 궁금증을 일으키게 쓰고, 한 줄 12자 안팎으로 최대 2줄이다. 예: `비린내 0%의 비밀`
  - 과장이나 사실이 아닌 내용은 쓰지 않는다. 답변에 나온 내용만 쓴다.
- 재미있거나 중요한 답변이 있는 주제를 먼저 놓아 `id` 순서를 정한다.

**질문/답변 구분**
- 인터뷰어의 질문 문장은 `question`, 인터뷰 대상자의 말은 `answer`로 구분한다.
- 애매한 구간은 `notes`에 적는다.

**질문 → 소제목 (`text`)**
- 질문 내용을 `Q. ` + 15자 안팎으로 요약한다.
- 전체본에서는 다음 질문이 나올 때까지 소제목이 자동으로 유지된다.
- 릴스에서는 릴스의 `title`이 소제목으로 쓰인다.

**답변 → 귀여운 자막 (`text`)**
- 한 자막은 1~2줄, 한 줄 14자 안팎으로 만든다. 두 줄이면 `\n`으로 줄을 바꾼다.
- 긴 문장은 단어별 시간을 이용해 자연스러운 곳에서 나누고, 각 조각에 정확한 시간을 준다.
- 말투(~요, ~죠)는 살린다.
- 화면에 0.6초 이상 머물러야 읽을 수 있다.

**주제 (`topics`)**
- 질문이 바뀔 때마다 주제를 하나 만든다. 색은 비워 두면 설정의 색상표가 순서대로 적용된다.
- 모든 질문, 답변, 릴스에 `topic`을 지정한다.

**강조 (`highlights`)**
- 답변 속 핵심 단어를 자막 하나에 0~2개 고른다. 예: 업체명, 메뉴, 효능, 숫자
- 자막 `text`에 들어 있는 글자 그대로 적는다.

**오타 (`fixes`)**
- 음성 인식이 틀린 단어를 고치고, 고친 내용을 기록한다.
- 고유명사(업체명, 메뉴명)를 특히 주의한다. 모르는 단어는 추측하지 말고 사용자에게 물어본다.

**얼굴 위치 (`crop.center_x`)**
- 얼굴 중심의 가로 위치를 0~1로 적는다. 0은 왼쪽 끝, 1은 오른쪽 끝이다.
- 원본이 세로 영상이면 0.5로 둔다.

**전체본 만들기 (`make_full`)**
- 기본값은 `true`다. 릴스만 필요하면 `false`로 둔다.

## outline.json 형식

시간은 모두 **원본 영상 기준 초**다. 답변 자막(`items`)은 쓰지 않는다. `step3`가 만든다.

```json
{
  "make_full": true,
  "crop": {"center_x": 0.5, "zoom": 1.0},
  "auto_silence": {"min_gap": 0.7, "pad": 0.12},
  "topics": [
    {"id": "t1", "name": "맛있게 먹는 법", "keywords": ["전문가", "부추", "생강"]}
  ],
  "questions": [
    {"start": 13.09, "end": 18.11, "text": "Q. 장어 제일 맛있게 먹는 법은?", "topic": "t1"}
  ],
  "cuts": [
    {"start": 597.25, "end": 621.8, "reason": "같은 말 반복"}
  ],
  "reels": [
    {"id": "01", "title": "Q. 장어 제일 맛있게 먹는 법은?", "hook": "장어, 제일 맛있게\n먹는 법?", "topic": "t1",
     "ranges": [[13.09, 18.11], [34.65, 48.63], [51.13, 78.95]]}
  ],
  "fixes": [{"from": "박리담회", "to": "박리다매"}],
  "notes": ["확인이 필요한 단어 등"]
}
```

- `keywords`: 그 주제의 답변 자막에서 강조할 단어 후보다. 자막 하나에 최대 2개까지 자동으로 강조된다.
- `fixes`: 자막 전체에 적용되는 바꿔치기다. 다른 단어 일부와 겹치지 않게 충분히 길게 적는다.
- 질문 구간(`questions`)의 말에는 답변 자막이 생기지 않는다. 대신 소제목이 나온다.

## 자동으로 들어가는 효과

효과는 `config.json`의 `effects`에서 바꾼다.
- **컷마다 번갈아 확대** (`punch_in_zoom`): 자른 자리(점프컷)가 티 나지 않고 리듬감이 생긴다.
- **천천히 줌인** (`slow_zoom`): 화면이 멈춰 있는 느낌을 없앤다.
- **첫 컷 등장 애니메이션** (`video_intro`)
- **글자 등장 애니메이션**: 훅, 소제목, 자막 각각
- 효과 이름을 찾지 못하면 그 효과만 건너뛴다. 이때는 사용자에게 알린다.

## 문제가 생기면

- **`pycapcut` 오류나 캡컷에서 프로젝트가 안 열릴 때**
  - 캡컷 버전 업데이트로 파일 형식이 바뀌었을 수 있다.
  - 오류 메시지를 그대로 보여주고, 캡컷 버전을 확인해 달라고 한다.
- **효과 때문에 프로젝트가 안 열리면** `config.json`의 해당 효과를 `null`로 바꾸고 다시 만든다.
- **`capcut_draft_dir`을 못 찾을 때**
  - 캡컷 설정 → 프로젝트(초안) 저장 위치를 확인해 달라고 한다.
- **그 밖에** 결과를 지어내지 않는다. 실패한 단계와 이유를 그대로 알린다.
